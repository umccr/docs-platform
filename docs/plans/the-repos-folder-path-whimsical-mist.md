# docs-platform becomes the home of docs.umccr.org; OrcaSonar becomes a new backend service

## Context

The team has decided to move all docs infrastructure, pipelines and Lambdas out of `frontend-infrastructure-pipelines/lib/docs/` (fip) and into `umccr/docs-platform`.

**Why:** docs-platform becomes the central place for docs.umccr.org, holding the infrastructure, the pipelines, the toolkit, the theme and the platform site. fip returns to serving the customer-facing portal UI only.

**At the same time, the new design is implemented:**
- the **docs.umccr.org Platform Design**: an organisation webhook, a dispatcher and one shared site pipeline; the export to OrcaSonar; and the chat panel as an OrcaSonar client;
- the **OrcaSonar Design**, in a new repository, `umccr/orcasonar`.

**What exists today:**
- **fip, on `feat/docs-umccr-org`:** 0 commits ahead of `main`; 37 changes, all staged, none unstaged.
- **Dev deployment:** only the beta stage stack was deployed. It is CloudFormation stack `OrcaBusBeta-DocsHostingStack`, deployed with `pnpm cdk deploy 'DocsInfrastructurePipeline/DeploymentPipeline/OrcaBusBeta/DocsHostingStack'`, per `docs-platform/deploy-dev.md`.
- **Toolchain:** the pipeline stack `DocsInfrastructurePipeline` was never deployed. docs-platform can therefore take over both stack names, provided construct IDs, stack names and physical names stay the same.

**Decisions:**
- **Layout:** docs-platform uses the OrcaBus service layout at its root.
- **Visibility:** docs-platform stays public. Account IDs come only from `@orcabus/platform-cdk-constructs` and are never written in the repo.
- **Terraform** stays in `umccr/infrastructure` (`cognito_aai/app_docs.tf` and `umccr_docs_domain`).
- **fip clean-up:** after the move is verified, reset fip, switch it to `main` and delete the empty branch.
- **OrcaSonar:** stateful and stateless stacks with two pipelines, as in the OrcaBus template.
- **Sites** publish to dev and prod only.
- **Branches:** the docs repos stay on `feat/docs-umccr-org`. The new repo gets `feat/orcasonar-initial`.
- **No commits and no pushes.** Leave the index alone, except for the fip reset, which the user asked for.

**Pipelines:**
- `OrcaBus-DocsInfrastructure`, now sourced from umccr/docs-platform;
- `DocsSitesPipeline`;
- `OrcaBus-OrcaSonarStatefulStack`;
- `OrcaBus-OrcaSonarStatelessStack`.

## Step 3: The new docs design, in docs-platform

### Infrastructure (`infrastructure/`, `app/`)

- **`sites.ts`:**
  - `DocsSite` becomes `{slug, repo, title, description, branch, configPath, docsPaths, toolkitRef, stages}`;
  - `publishEnvironments` and `publisherRoleName` are removed; validation is extended;
  - `dispatchRegistry()` serialises the registry for the dispatcher;
  - the platform site uses `toolkitRef: 'self'` (build with the toolkit at the pushed commit, as `site.yml` did) and `docsPaths` of `docs/**`, `mkdocs.yml`, `toolkit/**` and `requirements/build.txt`.
- **`config.ts`:**
  - `sonarApiUrl` per stage;
  - role names `docs-publisher` (stage) and `docs-sites-publish` (toolchain);
  - SSM `/docs/content-bucket-name`;
  - the GitHub OIDC settings are removed.
- **`stage/hosting-stack.ts`:**
  - **Publisher role:** the per-site roles and the GitHub OIDC provider become one role, `docs/docs-publisher`:
    - it trusts only `docs-sites-publish` in `TOOLCHAIN_ENVIRONMENT.account`;
    - it may list, put and delete under `sites/*`;
    - it may read `/docs/content-bucket-name` and `/orcasonar/ingest-bucket-name`;
    - its sessions last 1 hour.
  - **SSM:** write `/docs/content-bucket-name`.
  - **CSP:** content-page `connect-src` adds `https://sonar.<stage zone>` and `https://cognito-idp.<region>.amazonaws.com`.
  - **`env.js`:** gains `VITE_SONAR_API_URL`.
  - **Assets:** deploy `_auth/token.js`.
- **`app/auth-web/src/token.ts`:** builds to `token.js`. It reuses `configureAuth` and `getIdToken` from `src/auth.ts` and exposes `window.umccrDocsAuth.getIdToken()`, refreshing when the token is near expiry, plus the Sonar URL.
- **`toolchain/dispatcher.ts`** and **`app/dispatcher/`**
  - **Resources:**
    - a Lambda behind a function URL with auth NONE;
    - a generated Secrets Manager webhook secret;
    - a DynamoDB dispatch table holding delivery IDs (with a TTL) and a release counter per slug.
  - **Logic:**
    1. Verify `X-Hub-Signature-256` with a timing-safe compare.
    2. Accept only `push` events for a registered repository and branch.
    3. Filter the changed files against `docsPaths` with picomatch.
    4. Dedupe with a conditional put on the delivery ID.
    5. Take the next release number.
    6. Call `codebuild:StartBuild` on the fetch project with:
       - `sourceTypeOverride GITHUB`, the location, `sourceVersion <commit>`;
       - `sourceAuthOverride {CODECONNECTIONS, SSM codestar_github_arn}`;
       - environment variables SLUG, REPO, COMMIT, RELEASE, TOOLKIT_REF and CONFIG.
    7. Reply 202.
- **`toolchain/fetch-build.ts`:**
  - CodeBuild zips the checkout without `.git` to `sources/<slug>/<commit>.zip`;
  - then `aws codepipeline start-pipeline-execution` with an `S3_OBJECT_KEY` source revision and the variables;
  - a versioned source bucket with 30-day expiry.
- **`toolchain/sites-pipeline.ts`:** CodePipeline V2 in PARALLEL mode, with the variables SLUG, REPO, COMMIT, RELEASE and TOOLKIT_REF.
  - **Source:** S3, with trigger NONE and `AllowOverrideForS3ObjectKey` set by property override.
  - **Build:** read-only CodeBuild that installs the toolkit from `git+https://github.com/umccr/docs-platform@$TOOLKIT_REF#subdirectory=toolkit` and the hash-pinned `requirements/build.txt` from the same ref. It runs `check`, `build`, `verify-site` and `export-kb`.
  - **Publish dev, then Publish prod:** CodeBuild as `docs-sites-publish`, which may only assume the stage `docs/docs-publisher` roles. There is no approval stage.
  - **Notifications:** failed runs post to Slack through `/chatbot_arn/slack/alerts-build`.
- **`toolchain/infrastructure-pipeline.ts`:** the stack also creates the dispatcher, the fetch build and the sites pipeline. The pipeline's self-update deploys them.

### Toolkit and theme (`toolkit/`)

- **`export_kb.py`** and `umccr-docs export-kb`:
  - write processed Markdown: wikilinks resolved to page URLs, callouts and Bases converted, front matter removed;
  - beside each page, write `<path>.md.metadata.json` containing `{"metadataAttributes": {doc_id, site, title, url, commit, updated}}`.
- **`publish.py`:**
  - `--release N` skips when the live `_publish.json` holds a newer release, and records the release number;
  - `--role-arn` assumes the role with a session policy limited to `sites/<slug>/*` and `docs/<slug>/*`;
  - bucket names come from SSM;
  - a new `publish_documents()` mirrors `kb/` into `docs/<slug>/`, with the mass-delete guard. It skips with a warning when `/orcasonar/ingest-bucket-name` is absent.
- **`cli.py`:** adds `export-kb`, `publish-documents` and the new flags.
- **Theme** (`umccr.js`, `umccr.css`), the chat panel:
  - Ask and Search; the 30-day notice; the current site by default;
  - lazy-loads `/_auth/env.js` and `/_auth/token.js`;
  - sends `fetch` POST requests and parses SSE with a `ReadableStream`;
  - shows sources as docs links; thumbs up or down go to `/feedback`;
  - on `401`, refreshes the token once and retries; on `429` and `503`, shows a message.
- **Tests:** a new `toolkit/tests/test_export_kb.py`, and additions to `test_publish.py`.

**Setup.**

- **GitHub:** the user creates the GitHub repository later.

```text

  infrastructure/toolchain/{stateful,stateless}-stack.ts   DeploymentStackPipeline, githubOwner 'umccr'
```

**Stateful stack:**
- **Sonar KMS key:** its key policy allows `docs/docs-publisher` through S3.
- **Ingest bucket:** versioned, encrypted with the Sonar key, EventBridge notifications on. Its bucket policy lets `docs-publisher` list, put and delete under `docs/*`.
- **Records bucket:** `records/` and `feedback/` expire after 30 days; `eval-set/` is kept.
- **DynamoDB table `OrcaSonarTable-<stage>`:** with a TTL and point-in-time recovery.
- **Knowledge base:**
  - `CfnKnowledgeBase` with `managedKnowledgeBaseConfiguration`, encrypted with the Sonar key;
  - `CfnDataSource` named `docs`: the managed S3 connector on the bucket, prefix `docs/`.
- **Guardrail:** `CfnGuardrail` and a version.
- **SSM:** `/orcasonar/ingest-bucket-name`, and internal parameters for the stateless stack.

**Stateless stack** (no VPC):
- **API:**
  - a regional REST API with custom domain `sonar.<zone>`, using `/umccr/certificate_arn` and `/hosted_zone/umccr/*`;
  - CORS for the docs hosts, plus CORS on gateway responses;
  - WAF (`CfnWebACL` with the managed rule groups and a rate rule).
- **Authorizer:** a TOKEN authorizer using `aws-jwt-verify`, ID token only, client from `/cognito/docs-app/app-client-id`, cached for 5 minutes.
- **Chat Lambda:**
  - Hono `streamHandle`, behind a `LambdaIntegration` with `responseTransferMode STREAM`;
  - Bedrock permissions:
    - `Retrieve` on the knowledge base;
    - `InvokeModelWithResponseStream` on the `au.` Sonnet 5 and Haiku 4.5 profiles, and their models in ap-southeast-2 and ap-southeast-4;
    - `ApplyGuardrail`.
- **Query Lambda:** `/search`, `/documents/{id}`, `/feedback`, and `/health`, which has no authorizer.
- **Ingestion:**
  - `ingest-mark`: an EventBridge rule on changes under `docs/` sets a dirty flag;
  - `ingest-run`: every 15 minutes, starts one ingestion job if the flag is set.
- **Monitoring and budget:** alarms, a canary on `/health`, and a $50 AWS Budgets limit with a deny-Bedrock action. `/orcasonar/api-url` is written to SSM.

**App behaviour** follows the OrcaSonar Design page:
- a zod-validated body;
- the budget: the team allowance is the remaining budget ÷ the remaining days, and each reader gets $0.40 a day; over budget returns `429` with `Retry-After`;
- 6 turns of history; Retrieve the top 8 passages filtered by site;
- `ConverseStream` with the guardrail and `maxTokens` 1000;
- SSE events `meta`, `delta`, `citations`, `done` and `error`;
- record the cost and the turn, and write the record under `records/date=…/`;
- logs never hold the question.

**Tests:**
- **App, with vitest:** budget, SSE, the chat flow with `aws-sdk-client-mock`, the authorizer with a cached JWKS, and OpenAPI conformance.
- **Infrastructure, with jest + cdk-nag:** every stage, plus asserts for streaming, the open `/health` route and the `docs-publisher` grants.

## Contract between docs-platform and OrcaSonar

| Interface | Value |
| --- | --- |
| Ingest bucket | SSM `/orcasonar/ingest-bucket-name`, written by OrcaSonar. When it is missing, the docs publish skips the export with a warning. |
| Writer | `role/docs/docs-publisher` in each stage account, named in OrcaSonar's bucket policy and key policy |
| Objects | `docs/<slug>/<path>.md` plus `.md.metadata.json`; `doc_id` is `<slug>:<path without .md>` |
| API | `https://sonar.<dev\|stg\|prod>.umccr.org/api/v1`, from docs config |
| Token | Cognito ID token, client `docs-app`, sent as `Authorization: Bearer`, as in `orca-ui-v2/src/api/auth-middleware.ts` |
| CORS | `docs.dev.umccr.org`, `docs.stg.umccr.org`, `docs.umccr.org`, `docs.prod.umccr.org` |

## Order of deployment

These are steps for the user after review.
1. **Pipeline 1:** from docs-platform, `cdk deploy DocsInfrastructurePipeline` in the toolchain account, once. Its self-update then owns it. Beta picks up the single publisher role.
2. **Webhook:** an org owner creates the webhook, using the dispatcher URL and the secret.
3. **Platform site:** push `/platform/` and check that it reaches dev and prod.
4. **OrcaSonar toolchain:** `cdk deploy` both OrcaSonar toolchain stacks. The stateful pipeline deploys to beta, and docs exports start.
5. **OrcaSonar API:** the stateless pipeline deploys to beta. Release the toolkit tag with the chat panel and bump `toolkitRef`; the chat then works in dev.
6. **Gamma and prod:** each pipeline's approval promotes them.

**By hand, by an org admin:**
- set the Bedrock data-retention mode to `none`, plus an SCP that stops anyone changing it;
- enable model access for Sonnet 5 and Haiku 4.5;
- check that the AWS Connector app can see docs-platform and the site repos.
